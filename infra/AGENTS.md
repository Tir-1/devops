# AGENTS.md — стенд курса «Технологии DevOps», вариант 68

## Инварианты стенда
- Два узла Debian 13: `node-1` (платформа Gitea, registry, runner, control plane) и `node-2` (worker). Обращаться к ним только по именам, адреса не хардкодить.
- Вход по SSH только по ключу; `sudo` спрашивает пароль. Пароли и ключи в репозитории не хранятся.
- Порты снаружи: 22, 80, 443 на обоих узлах; 2222, 8443, 6443 — на `node-1`. Новый порт наружу не открывать.
- Всё, что меняется на узлах, описывается кодом в этом репозитории; ручная правка на узле — дрейф, её нужно перенести в код.
- Инструменты варианта фиксированы на семестр: менять их нельзя (Gitea, Woodpecker CI, kubeadm, werf, Prometheus/Loki).

## Команды проверки
- `ssh student@node-1 'docker compose ps'` — стек приложения жив.
- `ansible-playbook site.yml --check` — код и узлы совпадают.
- `<линтер приложения>` и `<тесты приложения>` — из README приложения.
- `curl -fsS https://node-1:8443/api/healthz` — платформа Gitea отвечает.
- Изменение считается готовым, только когда команда проверки отработала.

## Запреты
- Не передавать агенту секреты: приватные ключи, пароли, токены CI, содержимое `ansible-vault` и `.env`.
- Не выполнять на узлах команды, которых нет в дельте: сначала показать правки, потом применять.
- Не отключать проверки: TLS, подпись образов, гейты конвейера, защиту ветки.
- Не работать агентом в namespace `prod` и в репозитории окружений без ревью.
- Не коммитить сгенерированный код без чтения: ответственность за содержимое репозитория несёт студент.
